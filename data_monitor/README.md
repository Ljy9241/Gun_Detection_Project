# GPS 轨迹地图

运行 `python data_monitor/gun_wifi_monitor.py`，开始监听后切换到 **GPS 地图**。
需要 PyQt5、PyQtWebEngine、pyqtgraph；缺少时，在运行程序的同一个 Python 环境中安装：

```powershell
python -m pip install PyQt5 PyQtWebEngine pyqtgraph
```

高德 Web 端 JS API 的 `key` 和 `securityJsCode` 从本目录的 `amap_config.json` 读取。
该文件已被 Git 忽略，不应提交密钥。电脑必须能够访问高德在线服务。

## 操作

- 顶部下拉框选择每次上电的历史轨迹；“返回当前轨迹”恢复自动选择正在连接的设备。
- 起点为绿色，末次有效定位为蓝色，射击位置为红色；点击标记或轨迹线查看采样时间和原始 GPS 坐标。
- 自动跟随保持末次定位或回放位置居中，手动拖动地图后自动取消；“查看完整轨迹”缩放到整段轨迹。
- 播放/暂停、倍速、进度条和“回到起点”控制回放，按上电计时推进。GPS 无效或长时间缺测处断开连线。
- 没有有效 GPS 的射击事件会保存并统计，但不会虚构地图位置。
- “清空曲线”仅清理原有曲线缓存，不删除轨迹历史。

## 数据与固件

必须重新编译并烧录本次修改后的**普通固件**，才能准确区分每次上电，并补传断网期间的轨迹和射击位置。
每次启动生成独立的 64 位上电标识；每条新缓存记录携带该标识、64 位上电毫秒数和射击标识。
设备断网时继续缓存，恢复连接后补传。电脑在同一数据库事务内写入轨迹和去重凭据，提交后才向设备确认。
重复包不会重复生成轨迹点或射击标记，设备掉电重启后的旧缓存仍归入原来的上电轨迹。

轨迹保存在本目录的 `gun_telemetry.db`，重启电脑端后仍可选择查看。
升级时保留旧表，并将既有遥测导入“旧版未分组”；旧版设备缓存也能继续读取和补传。
旧记录没有上电标识，无法可靠重建上电分组；旧版回放计时仅用于展示采样顺序。
固件兼容读取 TLM1 缓存，新写入采用 TLM2，不主动清空旧缓存。

地图将 GPS 的 WGS-84 坐标转换为高德使用的 GCJ-02 显示坐标，数据库始终保留原始 GPS 坐标。
默认显示约每秒一个点，超长轨迹会增加显示间隔；起止点和射击位置保留，原始记录不因显示抽样而删除。
历史读取在后台执行；地图或网络加载失败不影响遥测入库。

现有硬件存储限制仍然存在：普通遥测累计 20 条后写入 Flash，突然断电最多可能丢失最后约 1 秒的 RAM 样本；
射击位置立即尝试写入 Flash。Flash 已满、损坏或不可用时无法保证继续记录，设备串口会报告失败。
容量测试固件仍按原有规则等待存储满后才补传，不适合实时轨迹使用。

## 验证

```powershell
python data_monitor/test_trajectory.py
node data_monitor/test_map.js
python data_monitor/test_trajectory.py --smoke
```

前两项验证数据库补传与地图交互；`--smoke` 在 Windows 后台创建临时数据库，使用本地配置实际加载高德地图。
它不会向真实遥测数据库写入演示数据。设备离线行走、掉电、补传的完整链路还需烧录后在实机上验证。

高德接入参考：[JS API 加载](https://developer.amap.com/api/javascript-api-v2/guide/abc/load)、
[安全密钥配置](https://developer.amap.com/api/javascript-api-v2/guide/abc/jscode)。
