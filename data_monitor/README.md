# GPS 轨迹地图

## 局域网自动发现

首次升级需烧录支持发现的新固件，并使用本版上位机；此后电脑 IP 改变无需再次烧录。
设备与电脑连接同一局域网，上位机监听地址使用 `0.0.0.0`、端口 `8888`，点击开始监听即可。
设备只需配置 Wi-Fi 名称、密码，不再配置电脑 IP。监听端口须与固件 `MONITOR_DISCOVERY_PORT` 一致。
允许 Windows 防火墙的 UDP 8888 入站通信，路由器/热点需允许客户端互通和广播。

设备联网时每 2 秒发送发现广播，上位机从接收数据的同一 UDP 套接字回复，
设备以回复的源 IP 和端口作为上传地址。发现包携带随机请求标识及协议版本，不写入遥测数据库。
连续 8 秒没有当前上位机的发现回复后，设备清除旧地址并重新发现；未确认的 Flash 记录继续保留和补传。
电脑换 IP 时保持监听 `0.0.0.0` 即可，正常联网时通常约 8–10 秒恢复。
多个上位机同时监听时选择首个有效回复，并保持使用它直到超时，建议同网段只开启一个上位机。
此协议用于可信局域网，请求标识用于匹配回复，不提供身份认证。

现有低功耗配置会关闭 Wi-Fi；此时暂停发现，运动唤醒或 Wi-Fi 窗口恢复后重新发现。

运行 `python data_monitor/gun_wifi_monitor.py`，开始监听后切换到 **GPS 地图**。
需要 PyQt5、PyQtWebEngine、pyqtgraph；缺少时，在运行程序的同一个 Python 环境中安装：

```powershell
python -m pip install PyQt5 PyQtWebEngine pyqtgraph colorama
```

高德 Web 端 JS API 的 `key` 和 `securityJsCode` 从本目录的 `amap_config.json` 读取。
该文件已被 Git 忽略，不应提交密钥。电脑必须能够访问高德在线服务。

## 仅传输模式

更新电脑端程序并烧录新的普通固件后，开始监听，等待设备连接，点击 **开始仅传输**。
界面会等待设备确认；收到确认后按钮变为 **恢复采集**，并显示待传记录、完成百分比和条/秒。
命令每 2 秒重试，30 秒未确认会提示超时；旧固件下按钮不可用。

仅传输时暂停声音、振动和射击检测，关闭 GPS，保持 Wi-Fi 联网；已有 RAM 遥测也会继续尝试写入并上传。
上传范围包括全部未确认的历史缓存。传完后保持暂停，断网后保持该模式并自动重连续传。
点击 **恢复采集** 才重新开始采集；重新上电始终默认正常采集。因此，从上电到按钮切换成功之间仍会产生正常数据。
停止电脑端监听不会让设备自动恢复采集。

上传优化使用紧凑的 JSON 数组格式，每批最多 7 条（原先 3 条），在同一事务中保存并确认整批记录，
并把设备端每条记录的 Flash 确认操作合并处理。仅传输时关闭 Wi-Fi 省电休眠。
仍保留 SQLite FULL 同步、提交成功才确认、补传去重机制；电脑端兼容旧版字典格式数据包。
新固件应配合更新后的电脑端使用。实际上传速度取决于 Wi-Fi、Flash 和电脑磁盘，应以界面测得的条/秒为准。

## 目录结构

```text
data_monitor/
├─ gun_wifi_monitor.py      # 启动入口，位置保持不变
├─ amap_config.json         # 高德密钥配置
├─ gun_telemetry.db         # 遥测与历史轨迹数据库
├─ README.md                # 使用说明
├─ monitor_lib/             # 内部功能模块
│  ├─ trajectory_map.py     # 地图界面
│  ├─ trajectory_store.py   # 轨迹存储
│  ├─ transfer_control.py   # 传输控制与数据包解析
│  └─ assets/
│     └─ trajectory_map.html
└─ tests/                   # 数据、传输与地图测试
```

`gun_telemetry.db-wal`、`gun_telemetry.db-shm` 是 SQLite 工作时生成的辅助文件，
`__pycache__` 是 Python 自动生成的缓存。启动入口、密钥和数据库仍在原位置。

## 操作

- 顶部下拉框选择每次上电的历史轨迹；“返回当前轨迹”恢复自动选择正在连接的设备。
- 起点为绿色，末次有效定位为蓝色，射击位置为红色；点击标记或轨迹线查看采样时间和原始 GPS 坐标。
- 自动跟随保持末次定位或回放位置居中，手动拖动地图后自动取消；“查看完整轨迹”缩放到整段轨迹。
- 播放/暂停、倍速、进度条和“回到起点”控制回放，按上电计时推进。同一次上电的有效定位点按时间顺序连线，缺测区间用前后两个有效点之间的直线表示。
- 没有有效 GPS 的射击事件会保存并统计，但不会虚构地图位置。
- “清空曲线”仅清理原有曲线缓存，不删除轨迹历史。

## 数据与固件

必须重新编译并烧录本次修改后的**普通固件**，才能准确区分每次上电，并补传断网期间的轨迹和射击位置。
每次启动生成独立的 64 位上电标识；每条新缓存记录携带该标识、64 位上电毫秒数和射击标识。
设备断网时继续缓存，恢复连接后补传。电脑在同一数据库事务内写入轨迹和去重凭据，提交后才向设备确认。
重复包不会重复生成轨迹点或射击标记，设备掉电重启后的旧缓存仍归入原来的上电轨迹。

轨迹保存在本目录的 `gun_telemetry.db`，重启电脑端后仍可选择查看。
升级时保留旧表，并将既有遥测导入“旧版未分组”；旧版设备缓存也能继续读取和补传。
旧记录没有上电标识，无法可靠重建上电分组；旧版回放计时仅用于展示采样顺序。
固件兼容读取 TLM1 缓存，新写入采用 TLM2，不主动清空旧缓存。

地图将 GPS 的 WGS-84 坐标转换为高德使用的 GCJ-02 显示坐标，数据库始终保留原始 GPS 坐标。
默认显示约每秒一个点，超长轨迹会增加显示间隔；起止点和射击位置保留，原始记录不因显示抽样而删除。
历史读取在后台执行；地图或网络加载失败不影响遥测入库。

现有硬件存储限制仍然存在：普通遥测累计 20 条后写入 Flash，突然断电最多可能丢失最后约 1 秒的 RAM 样本；
射击位置立即尝试写入 Flash。Flash 已满、损坏或不可用时无法保证继续记录，设备串口会报告失败。
容量测试固件仍按原有规则等待存储满后才补传，不适合实时轨迹使用。

## 独立轨迹周期和射击数据库

固件新增 `NORMAL_GPS_TRACK_INTERVAL_MS`（默认 1000 ms）、`NORMAL_SENSOR_RECORD_INTERVAL_MS`（默认 10000 ms）、`LOW_POWER_SENSOR_RECORD_INTERVAL_MS`（默认 10000 ms）。普通 GPS 常开时每秒保存独立轨迹，声音/振动按各模式独立周期保存；轨迹记录不会伪造额外的传感器行。低功耗 GPS 周期和夜间待机策略不变。

新固件发送 `compact-v2`，本版上位机同时兼容旧 `compact-v1`。升级时需要同时使用新固件及本版上位机，否则旧上位机无法确认新格式，设备会保留数据待补传。

在原来的 `gun_telemetry.db` 中新增 `shots` 表，只包含四列：

| 字段 | 内容 |
|---|---|
| shot_id | 设备本次开机的射击计数：1、2、3……，设备重启后重新从 1 开始，允许重复 |
| timestamp | 射击时间，北京时间或未校时的 T+ 时间 |
| latitude | 纬度；无有效定位时为空 |
| longitude | 经度；无有效定位时为空 |

实时射击、断网后的 Flash 补传和重复 UDP 包会合并为同一次射击。原有 `track_points` 表保留设备、上电标识、设备射击编号等去重信息；`shots` 用 SQLite 隐藏的 `rowid` 关联原轨迹记录，仅保留四个显示字段，不能把可重复的 `shot_id` 当作唯一键。通过数据库触发器，射击表与轨迹、上传确认凭据在同一个事务中提交，成功后才 ACK；写入失败不确认设备记录。

启动监听时自动回填原轨迹中的射击历史；若目录里存在上一步创建的 `gun_shots.db`，会只读导入其中记录到原库，按原设备/上电/射击身份去重。旧文件保留为备份，程序不再向它写入。

可用 SQLite 工具打开原来的 `gun_telemetry.db` 查询：

```sql
SELECT shot_id, timestamp, latitude, longitude FROM shots ORDER BY rowid;
```

`ORDER BY rowid` 按记录顺序查看，可以看到每次重启后从 1 开始的新计数段；按 `shot_id` 排序则会把不同开机的相同编号排在一起。旧的全局编号结构会在启动监听时自动迁移为设备计数，既有时间和位置保留。
