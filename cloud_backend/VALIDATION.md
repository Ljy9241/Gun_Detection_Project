# 本地接收服务验证记录

验证日期：2026-11-16。

## 结果

- 自动化接口测试：37 项通过，运行约 3.3 秒。
- 独立运行进程：通过 `start.ps1` 启动 Uvicorn，监听 `127.0.0.1:8000`。
- 实际本机 HTTP 请求：`/healthz`、`/docs`、`/openapi.json` 均返回 200；未携带凭据访问 `/api/v1/records` 返回 401。
- 隔离 Python 环境的依赖检查：`pip check` 通过。
- 已有受 Git 跟踪文件的空白检查：`git diff --check` 通过。

## 自动化测试覆盖

1. 上传成功后返回完整业务确认；响应丢失后的原批重发、新批次补传不重复记录。
2. 新服务实例重启后读取同一数据库，历史数据和去重结果保留。
3. 相同记录身份不同内容、同一 batchId 更换内容均返回 409；混合批次冲突时整批回滚。
4. 射击按设备、存储世代、启动标识和射击编号去重；重复持久化记录不重复增加射击数。
5. 两个单位的设备列表、明细、详情、射击列表及统计互相隔离；篡改 deviceId、tenantId 或记录 ID 无法越权。
6. 查询凭据与上传凭据不能互用；停用设备后拒绝上传，历史仍可查询。
7. 迟到补传归原事件日期；未校时记录不伪造日期；北京时间跨 UTC 日期边界正确。
8. uint64 最大值、序号跳跃、历史 boot、不同存储世代与三种紧凑协议格式。
9. 越界值、非法类型/时间、NaN、畸形 JSON、单批重复身份、空/过大批次及超限/分块请求体。
10. 注入数据库写入失败与 COMMIT 失败：返回 503、没有业务确认、不留下部分记录，恢复后可重试。
11. 并发重发同一记录只创建一条主记录和一个射击事件。
12. 分页上限与分类查询。

## 实际验证范围

采用文件型 SQLite。没有创建四个模拟设备；接口测试的临时身份和数据只用于测试数据库。实际运行数据库未预置单位、设备、通用密码或测试事件，需按 README 登记真实单位和设备。

尚未验证 ESP32 直连、5 台实机或压力容量、PostgreSQL/RDS、TLS 公网入口、OSS 归档、用户网页及阿里云部署。这些不属于本次接收服务的完成结论。

## 复现

在项目根目录执行：

```powershell
cloud_backend/.venv/Scripts/python.exe -m pytest cloud_backend/tests -q
cloud_backend/.venv/Scripts/python.exe -m pip check
./cloud_backend/start.ps1
```

测试依赖 Starlette 在较新 AnyIO 下有一条弃用提示，测试结果为通过；不将该提示当作功能失败。
